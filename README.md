# ProСвітло - База адрес

Статичні бази адрес для системи моніторингу відключень електроенергії ПроСвітло.

Областей у репозиторії шість, по файлу на кожну. **Істина про склад і обсяги — `version.json`**, а не цей README: розділи нижче написані не для всіх областей.

## Статистика

- **Населених пунктів**: 1,243
- **Вулиць**: 16,786
- **Будинків**: 343,844
- **Розмір**: 76 MB
- **Останнє оновлення**: 2 грудня 2025

## Структура

```json
{
  "Назва міста": {
    "Назва вулиці": {
      "Номер будинку": {
        "queue": "Черга відключення",
        "source_url": "Джерело даних"
      }
    }
  }
}
```

## Джерела даних

Дані зібрані з офіційних Excel файлів АТ "Хмельницькобленерго":
- https://hoe.com.ua/page/pogodinni-vidkljuchennja

## Використання

Backend сервер завантажує цей файл при старті для швидкого пошуку адрес та черг відключень.

## Тернопільська область — `addresses_te_v1.json`

Додано 14 вересня 2026.

- **Населених пунктів**: 1 049
- **Громад**: 58
- **Вулиць**: 10 911
- **Адрес**: 261 796 (з них 181 належать до кількох ГПВ-підчерг)
- **Розмір**: 5.5 MB

### Джерело

Публічне JSON API АТ «Тернопільобленерго» (сервіс «Чому немає світла?»,
платформа PowerOn): `https://api-poweron.toe.com.ua/api/pw_address_queues`
— API Platform, JSON-LD, без авторизації. 12 028 вихідних записів.

Ту саму платформу використовують Житомирська (таблиця адрес поки порожня)
та Львівська (резолв за особовим рахунком, не за адресою) області.

### Структура

Формат сумісний з `addresses_v3.json`, але **ключі простору імен розведені**:

```json
{
  "meta": { "region": "Тернопільська", "operator": {...}, "notes": [...] },
  "settlements": {
    "te::22042": {
      "settlement_id": 22042,
      "operator": "toe",
      "name": "Шляхтинці",
      "type": "",
      "hromada": "Байковецька громада",
      "katottg": null,
      "streets": { "вул. Тараса Шевченка": { "1": ["5.2"] } }
    }
  },
  "gav": { "te::22042": { "вул. ...": { "1": ["3"] } } }
}
```

### Чому окремий файл, а не дописано у v3

`settlement_id` в операторів **незалежні**. Зараз перетину немає
(hoe 25479–26929, toe 1–24724), але діапазони розділяє лише 755 значень,
і кожен оператор нумерує свої НП сам. Злиття в один простір ключів —
міна сповільненої дії, тому ключ має префікс оператора (`te::`).

### Відомі обмеження джерела

| Обмеження | Деталі |
|---|---|
| **КАТОТТГ відсутній** | поле `codeOtg` порожнє в усіх 12 028 записах |
| **Тип НП не публікується** | немає «с.» / «м.» / «смт» — поле `type` порожнє |
| **70 повторюваних назв НП** | 162 населені пункти; розрізняються лише за id оператора + громадою |
| **Будинки пачками** | джерело дає `buildingNames` рядком через кому, не окремими записами |
| **Нежитлові об'єкти в базі** | `б/н`, `вул. освітлення`, `водокачка`, `церква`, `базова станція` |
| **Вулиці без назви** | джерело подекуди пише лише тип (`вул. `) без назви |
| **Графік не машиночитний** | ГПВ-сітка зберігається як `rawHtml`; структурованих даних немає |

`1-А` нормалізовано в `1А` (як у Хмельницькій); решта токенів збережена дослівно.

**Прибрано 218 вулиць без жодного будинку** (з 11 129): обрати таку вулицю неможливо —
за нею нема чого вибирати другим кроком, а 175 із них були порожньою заглушкою `вул. `.
Жодної адреси при цьому не втрачено. Безіменні вулиці, за якими будинки Є (111 записів,
132 адреси), **збережені дослівно**: оператор публікує відключення під тим самим рядком,
і перейменування зламало б матчинг адрес.

**ГПВ і ГАВ — різні простори імен**, не стани одного графіка: ГПВ у `settlements`
(підчерги `1.1`…`6.2`), ГАВ окремо у `gav` (черги `1`…`10`, 114 019 адрес).
Поля `chergAchr`, `chergGvsp`, `chergSgav` у джерелі порожні для всіх записів — не переносились.

## Житомирська область — `addresses_zt_v1.json`

Додано 15 вересня 2026.

- **Населених пунктів**: 1 647
- **Вулиць**: 19 287
- **Адрес**: 362 910 — найбільша з усіх наявних областей
- З них **21 128 звільнених** від погодинних відключень (порожній список черг)
- **Розмір**: 5.7 MB

### Джерело

Стара пошукова сторінка АТ «Житомиробленерго»:
`https://www.ztoe.com.ua/unhooking-search.php` — класична PHP-форма (POST, cp1251),
каскад РЕМ → населений пункт → вулиця. Повний перелік по РЕМ віддається, якщо
додати в POST поле `all` (кнопка «показати ще N записів»). Уся область — 19 запитів.

Нове API оператора (`api-ztoe-poweron.inneti.net`, платформа PowerOn) адрес НЕ
містить: `pw_address_queues` порожня. Звідти беруться лише відключення.

### Чому «звільнені» адреси теж у базі

3 323 рядки джерела кажуть «В цей час не вимикається, за винятком випадків
аварійних відключень». Це **не** відсутність даних: адреса реальна, і мешканець
має отримувати сповіщення про аварійні та планові роботи. Такі адреси мають
**порожній список черг** — це означає «за графіком не вимикають», а не «невідомо».

### Відомі обмеження джерела

| Обмеження | Деталі |
|---|---|
| **КАТОТТГ відсутній** | не публікується |
| **Громади відсутні** | оператор групує по **РЕМ**; 143 повторювані назви НП розрізняються лише РЕМом |
| **Тип НП не публікується** | поле `type` порожнє |
| **Побутові / непобутові окремо** | на одну вулицю бувають різні набори будинків; злиті, тому будинок може мати кілька підчерг |
| **Підстанції серед «вулиць»** | трапляються записи виду `КТП-206` |
| **Розірвані номери** | джерело подекуди пише «118, А» замість «118А» — такі токени склеєно |

Номери будинків збережені в **канонічній формі** проєкту
(`app/services/house_number`): `15-А`, `15 А`, `15а` і латинське `15a` — це все `15А`.

### Ключі

`zt::{РЕМ}::{НП}` — простір імен оператора, як і в решті областей: оператори
нумерують незалежно, тож бази не зливаються в один файл.

## Львівська область — `addresses_lv_v1.json`

Додано 9 жовтня 2026.

- **Населених пунктів**: 1 908
- **Вулиць**: 20 039
- **Адрес**: 461 760
- **З громадою й КАТОТТГ**: 1 770 НП (96,5 % адрес)
- **Розмір**: 7.8 MB

### Джерела — два, бо жодне поодинці не повне

| | що дає | чого не дає |
|---|---|---|
| PDF «Графік погодинного відключення (ГПВ) ПрАТ «Львівобленерго» на 2024-2025 роки», 456 с. | адреса → черга | жодного розрізнювача: сама лише назва НП |
| `power-api.loe.lviv.ua` (`pw_cities`, `pw_streets`) | громада, КАТОТТГ, 23 619 вулиць | черг немає взагалі — резолв за особовим рахунком |

### Таксономія — 3×2, а не 6×2

Шість підчерг (1.1 … 3.2). Це не половина файлу: черг 4.x-6.x у ньому немає
жодного разу, а покриває він 1630 НП із 1709, відомих їхньому ж API.

### Головна пастка PDF

Колонка «№ черги» — обʼєднані клітинки на пів сотні рядків, і підпис у них
вертикально **центрований**. Розрив сторінки ріже клітинку навпіл, а підпис
лишається тільки в одній половині — з 1479 клітинок 448 порожні (243 внизу
сторінки, 205 угорі наступної).

Через це «перенести останнє бачене значення вниз» дає неправильну чергу щоразу,
коли підпис блоку відрендерився на наступній сторінці: так увесь масив Верхнього
Синьовидного (126 рядків) отримував 1.2 замість 3.1, а всього помилок було 2059.

Тому черга береться з **геометрії**: горизонтальні лінії дають межі клітинок,
підпис шукається за координатою всередині них, половинки зшиваються назад.

### Звірка

Власник вручну пройшов документ і виписав усі 10 місць, де черга змінюється.
Розбір відтворив їх до одного (`REFERENCE_BOUNDARIES` у `parse_lviv.py`), і
парсер падає, якщо колись перестане. Нова редакція PDF із іншою версткою не
зможе тихо роз'їхатися.

### Однойменні села

140 назв в області належать двом-трьом різним селам (три Миколаєви, два
Поріччя…). У PDF немає нічого, крім назви, тож розрізняємо за **вулицею**:
дивимось, у якого з кандидатів така вулиця є в `pw_streets`. Збігся рівно один —
беремо його громаду й КАТОТТГ (2861 рядок). Збіглося кілька або жоден — запис
лишається з підписом «громаду не визначено» (3,5 % адрес), а не прилипає до
найбільшого кандидата навмання.
