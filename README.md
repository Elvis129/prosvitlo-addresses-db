# ProСвітло - База адрес

Статичні бази адрес для системи моніторингу відключень електроенергії ProСвітло.

Областей у репозиторії чотирнадцять (з Києвом), по файлу на кожну; у Дніпропетровської два файли — по одному на оператора. **Істина про склад і обсяги — `version.json`**, а не цей README: розділи нижче написані не для всіх областей.

## Громади й коди КАТОТТГ

З версії 3.9–3.10 кожна область має громаду й національний код населеного пункту
з державного кодифікатора (Мінрозвитку, редакція наказу від 07.07.2026). Підпис
`display` тепер «с. Антопіль (Андрушівська громада)» замість назви РЕМу чи дільниці —
так однойменні села розрізняються з першого погляду.

| область | зіставлено | що додано |
|---|---|---|
| Хмельницька | 1371 / 1381 | (було раніше) |
| Закарпатська | 565 / 567 | код (громаду дав оператор) |
| Тернопільська | 1043 / 1047 | код (громаду дав оператор) |
| Івано-Франківська | 789 / 796 | громада + код |
| Житомирська | 1603 / 1647 | громада + код |
| Миколаївська | 811 / 881 | громада + код |
| Чернівецька | 418 / 461 | громада + код |

Незіставлені записи **свідомо** лишились зі старим підписом: хибна громада гірша за
жодну. Серед них — «близнюки» (два однойменні села в одній зоні оператора, зведені
джерелом в один запис), залізничні станції й частини міст, яких кодифікатор не має
як окремих НП, і адреси з сусідніх областей, які обслуговує оператор.

Ключі, назви, вулиці й черги при цьому не змінювались — додано лише підписи й коди.
Скрипт зіставлення: `prosvitlo-address-parser/enrich_katottg.py`.

## Тернопільська область — `addresses_te_v1.json`

Додано 14 вересня 2026.

- **Населених пунктів**: 1 049
- **Громад**: 58
- **Вулиць**: 10 911
- **Адрес**: 261 796 (з них 181 належать до кількох ГПВ-підчерг)
- **Розмір**: 5.5 MB

### Джерело

Публічне JSON API АТ «Тернопільобленерго» (сервіс «Чому немає світла?»,
платформа PowerOn): `https://api-poweron.toe.com.ua/api/pw_address_queues`
— API Platform, JSON-LD, без авторизації. 12 028 вихідних записів.

Ту саму платформу використовують Житомирська (таблиця адрес поки порожня)
та Львівська (база з `pw_accounts` по вулицях — див. розділ Львівської області) області.

### Структура

Формат сумісний з `addresses_v3.json`, але **ключі простору імен розведені**:

```json
{
  "meta": { "region": "Тернопільська", "operator": {...}, "notes": [...] },
  "settlements": {
    "te::22042": {
      "settlement_id": 22042,
      "operator": "toe",
      "name": "Шляхтинці",
      "type": "",
      "hromada": "Байковецька громада",
      "katottg": null,
      "streets": { "вул. Тараса Шевченка": { "1": ["5.2"] } }
    }
  },
  "gav": { "te::22042": { "вул. ...": { "1": ["3"] } } }
}
```

### Чому окремий файл, а не дописано у v3

`settlement_id` в операторів **незалежні**. Зараз перетину немає
(hoe 25479–26929, toe 1–24724), але діапазони розділяє лише 755 значень,
і кожен оператор нумерує свої НП сам. Злиття в один простір ключів —
міна сповільненої дії, тому ключ має префікс оператора (`te::`).

### Відомі обмеження джерела

| Обмеження | Деталі |
|---|---|
| **КАТОТТГ відсутній** | поле `codeOtg` порожнє в усіх 12 028 записах |
| **Тип НП не публікується** | немає «с.» / «м.» / «смт» — поле `type` порожнє |
| **70 повторюваних назв НП** | 162 населені пункти; розрізняються лише за id оператора + громадою |
| **Будинки пачками** | джерело дає `buildingNames` рядком через кому, не окремими записами |
| **Нежитлові об'єкти в базі** | `б/н`, `вул. освітлення`, `водокачка`, `церква`, `базова станція` |
| **Вулиці без назви** | джерело подекуди пише лише тип (`вул. `) без назви |
| **Графік не машиночитний** | ГПВ-сітка зберігається як `rawHtml`; структурованих даних немає |

`1-А` нормалізовано в `1А` (як у Хмельницькій); решта токенів збережена дослівно.

**Прибрано 218 вулиць без жодного будинку** (з 11 129): обрати таку вулицю неможливо —
за нею нема чого вибирати другим кроком, а 175 із них були порожньою заглушкою `вул. `.
Жодної адреси при цьому не втрачено. Безіменні вулиці, за якими будинки Є (111 записів,
132 адреси), **збережені дослівно**: оператор публікує відключення під тим самим рядком,
і перейменування зламало б матчинг адрес.

**ГПВ і ГАВ — різні простори імен**, не стани одного графіка: ГПВ у `settlements`
(підчерги `1.1`…`6.2`), ГАВ окремо у `gav` (черги `1`…`10`, 114 019 адрес).
Поля `chergAchr`, `chergGvsp`, `chergSgav` у джерелі порожні для всіх записів — не переносились.

## Житомирська область — `addresses_zt_v1.json`

Додано 15 вересня 2026.

- **Населених пунктів**: 1 647
- **Вулиць**: 19 287
- **Адрес**: 362 910 — найбільша з усіх наявних областей
- З них **21 128 звільнених** від погодинних відключень (порожній список черг)
- **Розмір**: 5.7 MB

### Джерело

Стара пошукова сторінка АТ «Житомиробленерго»:
`https://www.ztoe.com.ua/unhooking-search.php` — класична PHP-форма (POST, cp1251),
каскад РЕМ → населений пункт → вулиця. Повний перелік по РЕМ віддається, якщо
додати в POST поле `all` (кнопка «показати ще N записів»). Уся область — 19 запитів.

Нове API оператора (`api-ztoe-poweron.inneti.net`, платформа PowerOn) адрес НЕ
містить: `pw_address_queues` порожня. Звідти беруться лише відключення.

### Чому «звільнені» адреси теж у базі

3 323 рядки джерела кажуть «В цей час не вимикається, за винятком випадків
аварійних відключень». Це **не** відсутність даних: адреса реальна, і мешканець
має отримувати сповіщення про аварійні та планові роботи. Такі адреси мають
**порожній список черг** — це означає «за графіком не вимикають», а не «невідомо».

### Відомі обмеження джерела

| Обмеження | Деталі |
|---|---|
| **КАТОТТГ відсутній** | не публікується |
| **Громади відсутні** | оператор групує по **РЕМ**; 143 повторювані назви НП розрізняються лише РЕМом |
| **Тип НП не публікується** | поле `type` порожнє |
| **Побутові / непобутові окремо** | на одну вулицю бувають різні набори будинків; злиті, тому будинок може мати кілька підчерг |
| **Підстанції серед «вулиць»** | трапляються записи виду `КТП-206` |
| **Розірвані номери** | джерело подекуди пише «118, А» замість «118А» — такі токени склеєно |

Номери будинків збережені в **канонічній формі** проєкту
(`app/services/house_number`): `15-А`, `15 А`, `15а` і латинське `15a` — це все `15А`.

### Ключі

`zt::{РЕМ}::{НП}` — простір імен оператора, як і в решті областей: оператори
нумерують незалежно, тож бази не зливаються в один файл.

### Громади й коди КАТОТТГ (з 3.9.0)

Оператор громад не публікує, тож до 3.9.0 однойменні села розрізнялись лише
РЕМом: «с. Іванівка (Звягельський РЕМ)». Тепер `hromada`, `katottg` і `display`
взято з державного кодифікатора (Мінрозвитку, редакція наказу від 07.07.2026):
«с. Антопіль (Андрушівська громада)».

- **Зіставлено 1 603 з 1 647** (97,3%): 1 255 — за унікальною назвою й типом НП,
  335 — серед однойменних за районом і громадами, що їх обслуговує той самий РЕМ,
  1 — перейменоване (стара редакція кодифікатора → той самий код), 4 — з іншим
  типом НП, ніж у кодифікаторі, 8 — сільради (лише громада, без коду НП).
- **44 лишились із підписом РЕМу** — свідомо. 30 із них, найімовірніше, «близнюки»:
  в одному РЕМі два однойменні села, а джерело звело їх в один запис. Хибна
  громада гірша за жодну: вона сказала б людині, що вона в іншому селі.
- **Назви з апострофом** у джерелі закодовані як HTML (`П&#039;ятигірка`). Ключі
  й `name` лишено як є — за ними шукаються збережені адреси; розкодовано лише
  `display`.

Ключі, назви, вулиці й черги не змінювались — додано лише підписи й коди.

## Львівська область — `addresses_lv_v1.json`

Додано 20 жовтня 2026 (3.17.0) — з живої таблиці оператора, а не з PDF.

- **Населених пунктів**: 1 868 (код КАТОТТГ — у 1 846)
- **Вулиць**: 21 933
- **Адрес**: 502 816, з них 13 792 без черги ГПВ — у базі з порожнім списком
  («Не входить», «Інший ОСР», «Генерація»)
- **Підчерги**: 1.1 … 6.2; 1 740 будинків мають дві-три
- **Розмір**: 8.8 MB

### Як зібрано

`pw_accounts` (PowerOn) по кожній вулиці: 23 630 запитів, ліміт 429 тримав обхід
близько двох діб (`fetch_lviv_api.py` у `prosvitlo-address-parser`). Рядок джерела —
особовий рахунок (без персональних даних), тож у будинку їх багато; черга будинку —
обʼєднання черг його рахунків.

### Ключі й КАТОТТГ

- **Поле `katottg` у джерелі — код ГРОМАДИ, а не НП**: у Підгірців, Лучківців,
  Новичини… той самий `UA46040050000062043`. Узятий як є, він злив би різні села
  в одне. Код НП знайдено в кодифікаторі (2026-07-07) за назвою **всередині цієї
  громади**: однозначно — 1 846. Без коду лишились 17 назв, яких у кодифікаторі
  немає (серед них «Київське шосе» — не НП), і 5 пар однойменних сіл в одній
  громаді (два «Лісове» в Буській) — не вгадано.
- Ключ — `lv::{код НП}`, без коду — `lv::{громада}::{назва}`. Оператор пише одне
  село по-різному («Верхній лужок» / «Верхній Лужок»): за кодом вони одне.
- Назва НП — як у кодифікаторі, громада — з джерела.

### Назви вулиць — без типу

Оператор пише «Городоцька», а не «вул. Городоцька». Пошук бекенду з 20.10.2026 тип
вулиці не вимагає (`fix(search)`), тож «Львів, вул. Городоцька» знаходить її.

### Історія: чому відкликали PDF-версію (3.6.0 → 3.6.1)

Його зібрано з PDF «ГПВ ПрАТ «Львівобленерго» на 2024-2025 роки». У тому файлі є
лише черги 1.1-3.2, і з цього було зроблено висновок, що в області таксономія 3×2.

Висновок неправильний. PDF зроблено в Excel **27.08.2024**, і відтоді система черг
змінилася: на графіку оператора за 10.04.2026 черг **дванадцять** (1.1 … 6.2), а в
їхній живій таблиці трапляються 4.2 і 5.2. Тобто приписка адрес до черг не «лишалася
незмінною два роки» — PDF просто застарів.

Віддавати таку базу означало б показати людині правдоподібну, але чужу чергу
(«2.1» у сітці є, тож нічого не виглядало б зламаним). Це гірше за «даних немає».

### Де правильне джерело

`https://power-api.loe.lviv.ua/api/pw_accounts` — та сама платформа PowerOn, що в
Тернополя, Житомира й Закарпаття, і та сама структура, що в закарпатській
`pw_address_queues`:

```
buildingName, chergGpv, chergGav, chergAchr, chergGvsp, chergSgav
```

П'ять типів черг на будинок. **Персональних даних у відповіді немає** — попри назву
колекції, імен і номерів рахунків вона не віддає. Фільтрується за `city.id` +
`street.id`; `pagination=false` на велике місто валить сервер у 500, тож вивантаження
доведеться робити поступово. Є ліміт запитів (429) — ходити треба повільно.

### Що лишилося корисного з PDF-підходу

Техніка розбору (`parse_lviv.py` у `prosvitlo-address-parser`): колонка «№ черги» там
— обʼєднані клітинки з ЦЕНТРОВАНИМ підписом, і розрив сторінки лишає підпис лише в
одній половині (448 клітинок із 1479 порожні). Просте перенесення значення вниз
помиляється на 2059 адрес. Читати треба межі з горизонтальних ліній і зшивати
половинки. Якщо оператор колись перевидасть адресний PDF — це знадобиться.

## Чернівецька область — `addresses_cv_v1.json`

Додано 10 жовтня 2026.

- **Населених пунктів**: 461
- **Вулиць**: 14 013
- **Адрес**: 240 544
- **Розмір**: 3.7 MB

### Джерело — найдешевше з усіх

`oblenergo.cv.ua/shutdowns-search/{1..12}/` — по сторінці на дільницю, **12 запитів
на всю область**. Для порівняння: Львів коштував би 23 619 запитів, Київ ~100 000,
Закарпаття 390.

Так вийшло, бо їхній «Пошук групи» працює повністю на КЛІЄНТІ: JS фільтрує таблицю,
яка вже лежить у HTML. Тобто сторінка дільниці — це і є готовий дамп адреса→група.

```html
місто (дільниця 1):  <p>вулиця</p><b>будинок</b><u>група</u>
дільниці 2…12:       <s>НП</s><p>вулиця</p><b>будинок</b><u>група</u>
```

### Таксономія — ПЛОСКА, 12 груп

`Група1`…`Група12`, без крапкової нотації й **без підчерг**. Це не 6×2, як у
більшості областей, а дванадцять самостійних груп. Писати їх як «1.1» було б
вигадкою: оператор так не пише, і зіставити з його ж графіком не вийшло б.

### Розрізнювач — дільниця

517 НП на 12 дільниць, однойменні трапляються: 21 назва повторюється між дільницями.
Дільниця живе в ключі та в `rems`, а **не** в `hromada` — це різні рівні поділу, і
підміняти одне одним означало б зробити дані брехливими. Громад оператор не публікує.

### Що довелося полагодити

Оператор пише ту саму назву двояко — здебільшого великими («БАНИЛІВ», 1423 адреси),
але подекуди звичайними («Банилів», 1 адреса). Без згортання регістру це два різні
села, і людина, чия вулиця потрапила в менший запис, не знайшла б решти своєї. Таких
пар **47**, і в них було 16 % адрес області. Ключ згорнуто за регістром, а показується
те написання, яке оператор уживає частіше.

Окремо: у дільницях Герцаївська, Глибоцька й Новоселицька трапляються записи з НП
«Чернівці» на 1-4 адреси — найімовірніше описки оператора. Дільниця їх коректно
відділяє від самого міста, тож зливати їх не можна.

прода, на відміну від Вінниці, Чернівців, Волині та Львова.

### Типи черг — плутати не можна

| type_id | що це | значення |
|---|---|---|
| 1 | ГАВ | 20: `1…10` і `1(Р)…10(Р)` |
| 2 | СГАВ | 3 |
| **3** | **ГПВ** | **12: `1.1`…`6.2`** ← беремо лише це |

### Чому обхід дворежимний

Виміряно: **вулиця дорівнює одній черзі лише поза містом.**

- Костянтинівка, Арбузинка — усі вулиці 4.2; Андріївка, Архангельське — усі 3.1
- м. Миколаїв, вул. Маріупольська — **5 різних черг** на 25 будинках; Шевченка — 3

Тому місто обійдено по кожному будинку, а село — пробами: спершу на рівні НП (по
будинку з трьох різних вулиць), і лише якщо проба розійшлася — вулиця за вулицею.
97 % сільських вулиць виявилися однорідними, що зрізало обхід із ~75 тисяч запитів
до ~45.

Проби беруться **врозкид, а не підряд**: на Маріупольській перші чотири будинки
дають 2.2, а далі йде 5.2 — послідовна вибірка «перші три» збрехала б упевнено.

### Будинки без ГПВ ЛИШАЮТЬСЯ в базі

36 587 адрес не мають погодинної черги. Перевірено на вибірці: приблизно 56 % дають
повністю порожню відповідь API, а 44 % мають ГАВ і/або СГАВ, але не ГПВ.

Спершу вони були викинуті з бази — і це була **помилка**. Бек розрізняє три стани, а
не два: «адреси не існує» (`None`), «адреса є, але звільнена від ГПВ» (`exempt`) і
«адреса з чергою». Викинувши адресу, ми перетворюємо другий стан на перший — людина,
яка живе за реальною адресою, не може її навіть додати.

Так само зроблено в базі Житомира: там 21 128 адрес із порожньою чергою.

Практичний наслідок: коли зʼявиться ГАВ, ті ~15 тисяч адрес з аварійними чергами вже
будуть збережені в людей, і вони одразу почнуть отримувати інформацію — без
перебудови бази й без прохання «додайте адресу заново».

  без номерів», прізвища й позначки замість номерів.

  люди досі шукають за нею. Таблиці відключень дужок не пишуть — бек зводить їх до
  написання бази без урахування дужок.
- **Описки в колонці громади не породжують сіл-двійників**: пара (громада, НП), якої
  немає в кодифікаторі, зливається з єдиним однойменним записом, який там є (3 випадки).

  якщо різні — вулицю опитано поштучно (655 вулиць, 41,6 тис. будинків; на 633 з них
  будинки справді в різних чергах).

Разом ~540 тис. запитів за тиждень (`fetch_dnipro_yasno.py` у `prosvitlo-address-parser`).
Вибірку з 22 адрес звірено з живим API 28.10.2026 — усі збіглися.

### Ідентифікатори Yasno нестабільні

27.10.2026 Yasno перенумерував будинки, а id вулиць зсуваються, коли додаються нові
(«вул. Мальовнича Балка» в Дніпрі: 1939 → 1942). У базі тому лише назви. Поштучне
опитування сіл ішло вже після зміни: збирач спершу шукає поточний id вулиці за назвою,
а 4 вулиці, опитані за старим id (Вільне), перевірено й перезібрано.

### Що зведено

- **Вводи.** Yasno записує окремо «2 ввод 1» і «2 ввод 2» — це один будинок 2, і він
  отримує черги всіх своїх вводів.
- **Один НП під кількома id.** Перейменоване місто під обома назвами (Новомосковськ /
  Самар), два різні апострофи (Кам’янське), «с.» і «сел» одного села — 115 записів
  на 57 кодів КАТОТТГ злито в один запис під чинною назвою.
- **Не населені пункти.** Записи-дороги, сільради й «ТГ» цілком, «(пусто)» не включено;
  так само вулицю-заповнювач, яку Yasno ставить під 3+ НП (напр., «вул. Заплавна»
  з 1 299 будинками під 53 записами).

### Населені пункти без громади

Району Yasno не дає, а однойменних сіл в області багато: у Yasno одна «Андріївка», в
кодифікаторі їх 9. Такі записи (224) лишились без громади й коду — хибна громада гірша
за жодну. Сюди ж — старі назви, які Yasno ще тримає (Чапаєвка, Ленінське), і Таромське,
що тепер у межах Дніпра. Де однакові підписи мають різні типи НП, тип додано
(«с. Божедарівка» / «с-ще Божедарівка» — обидва в Божедарівській громаді).

### `settlement_id` (з 3.20.1)

`1 200 000 + id міста в Yasno`; сам id Yasno — у полі `yasno_city_id`. У 3.20.0 це був
id Yasno як є (1…1105) — ті самі числа, що й `settlement_id` Тернопільської бази, і
сервер за id знаходив тернопільське місто замість села Дніпропетровщини (16 НП:
Пушкарівка → Кременець, Калинове → Тернопіль…). `settlement_id` мусить бути унікальним
на всі бази. ЦЕК id не мала зовсім — тепер 1 203 001…1 203 014, зафіксовані в
`parse_cek.py`.

### Що з цим робить застосунок

Планових і аварійних ДТЕК відкрито не публікує: для цих адрес застосунок показує лише
графік (як для Києва).
